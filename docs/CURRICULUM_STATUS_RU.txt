ПРОВЕРКА ОФИЦИАЛЬНЫХ ИСТОЧНИКОВ НА GITHUB PAGES
Исправление curriculum-pages-v1 для Kitsune Math 3.1.0-rc.6.

ПРОБЛЕМА И РЕЗУЛЬТАТ
Прежний интерфейс запрашивал /api/curriculum-status у любого сайта.
Этот обработчик был только в LAN_SERVER.py, поэтому на GitHub Pages
появлялся ошибочный совет запускать START_LAN.bat.
Теперь Pages получает опубликованный отчёт. Прямой локальный API
сохранён для локальных адресов; при его отсутствии тоже используется отчёт.

КАК РАБОТАЕТ
.github/workflows/curriculum-status.yml проверяет пять записей источников
из curriculum-sources-v302.js (четыре уникальных адреса ЕДСОО и ФИПИ).
Запуски: после добавления/изменения сборщика в main, вручную через Actions
и по ежедневному расписанию 03:23 UTC. GitHub может задерживать плановый
запуск; интерфейс показывает фактическую дату сформированного отчёта.

Проверяется ответ официальной страницы и контрольный отпечаток её текста.
Это сигнал о доступности/изменениях страницы, а не автоматическое заключение
о содержании нормативного документа или соответствии всех уроков.
Первая успешная проверка создаёт базу сравнения; исторические изменения
с 15.09.2026 ей автоматически не восстанавливаются.
Карты уроков и дата содержательной сверки курса не меняются сборщиком.
Обнаруженный сигнал о необходимости сверки сохраняется до подтверждённой
содержательной проверки с более поздней датой courseVerifiedAt.

Отчёт сохраняется обычным коммитом в отдельной ветке kitsune-curriculum-status.
Первый коммит этой ветки содержит только curriculum-status.json, без модели
и истории приложения. main, установленный сайт и настройка Pages при
каждой ежедневной проверке не изменяются и не пересобираются.
Это также избегает зависимости от нового запуска Pages после коммита,
созданного GITHUB_TOKEN: GitHub не запускает обычные workflow по такому push.
История отчётов не переписывается; конкурентный push отклоняется штатным Git.
Если владелец добавил другие файлы в ветку отчётов, они сохраняются.

Устройства читают открытый JSON через raw.githubusercontent.com, уже
разрешённый действующей политикой приложения. При недоступности этого
адреса используется bundled curriculum-status.json; затем последний
сохранённый отчёт браузера. Старый отчёт не заменяет более свежий.
Service worker не сохраняет меняющийся JSON как неизменную часть оболочки.
Ни ключи доступа, ни пользовательские результаты в запросы не включаются.

КНОПКИ И ДАТЫ
«Обновить результаты» получает последний доступный отчёт и не запускает
новую серверную проверку от имени каждого посетителя.
«Обновлять результаты при запуске» можно включать/выключать. Автоматическое
получение ограничено одним разом в сутки на устройстве; ручное доступно всегда.
Офлайн сохраняется настоящая прежняя дата. Если первый отчёт ещё не создан,
интерфейс честно пишет, что проверка не выполнена, и оставляет официальные
ссылки. Частичные ошибки источников не выдаются за успешную проверку всех.

ПЕРВАЯ ПУБЛИКАЦИЯ И ПРОВЕРКА
Добавить все файлы исправления, включая скрытую папку .github/ и tools/.
Сохраняется существующий адрес /algebra8-course/, manifest и ключи прогресса.
После push в main открыть Actions → «Проверка официальных источников».
Дождаться зелёного выполнения; если первый запуск не появился, использовать
Run workflow на main. Потребуются разрешённые в репозитории GitHub Actions
и запись GITHUB_TOKEN в ветку отчётов (contents: write задаётся для этой job).
В браузер этот токен не попадает. Если серверная политика запрещает запись,
ошибка останется в журнале Actions; разрешения владельца самовольно не менять.

Проверить появление kitsune-curriculum-status/curriculum-status.json:
schema=1, mode=github-actions-check, checkedAt с фактической датой,
successCount и отдельные ok/error соответствуют результатам запросов.
Дождаться обновления Pages и применить «Обновить сейчас» в PWA.
Открыть «Источники и нормативная база», нажать «Обновить результаты».
Нужно увидеть дату отчёта, прежнюю дату сверки курса и реальные статусы.
Затем отключить сеть: результаты остаются видны, дата не становится «сегодня».
Проверить привычный урок, прогресс, читалку и голос. Очищать данные сайта
или переустанавливать PWA для этого исправления не требуется.

ПРОВЕРКИ И ОГРАНИЧЕНИЯ
Новые тесты проверяют интерфейс, сборщик, неизменность main/индекса Git,
историю отдельного отчёта и отказ при конкурентной публикации.
В Windows этой ограниченной сессии для трёх тестов издателя имитируется
только транспорт между временными репозиториями. Деревья, объекты, коммиты
и проверку истории выполняет настоящий Git. На Linux/GitHub Actions те же
тесты используют настоящий локальный push/fetch в тестовую bare-копию.
Живой запуск GitHub Actions и реальное обновление браузера здесь не выполнены;
это обязательные проверки после применения пакета, а не уже доказанный деплой.
