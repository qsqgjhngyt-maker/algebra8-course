# Запуск, публикация и откат

## GitHub Pages

Рабочий адрес: `https://qsqgjhngyt-maker.github.io/algebra8-course/`. Сохранение имени репозитория и пути важно для PWA, локальных данных и настройки облачного Origin. Публикуется текущая ветка через существующую настройку Pages; новую внешнюю инфраструктуру создавать не требуется.

Перед публикацией: синхронизируйте version.json, index, версию cache в sw.js и версии URL; выполните актуальные проверки; проверьте отсутствие приватных ключей и тестовых дампов. `.nojekyll` нужен для статической публикации. Не коммитьте node_modules, Python-кэш, скачанные модели, ZIP-сборки и локальные данные браузера. Архивы LOCAL/PATCH прикрепляются к GitHub Release.

Порядок: QA → проверка diff → один понятный commit → push без force → GitHub Release → проверка опубликованного version.json, manifest, ресурсов и статуса Pages. Не выдавайте успешный push за успешное развёртывание: дождитесь фактического обновления сайта.

## LOCAL

Нужен Python 3. Распакуйте LOCAL в отдельную папку, запустите `START_LAN.bat` либо `python LAN_SERVER.py --port 8080`. На компьютере используйте `http://127.0.0.1:8080/`. Сервер слушает локальную сеть: используйте доверенный Wi-Fi, не открывайте порт в интернет и завершайте процесс после работы. Через file:// не проверяются service worker, обновление и облачная авторизация.

## Cloudflare

Публикация Pages не запускает деплой Cloudflare Worker. В этой версии действующая точка входа `cloudflare-broker/src/index.js` сохранена без изменения поведения. Удалены лишь неиспользуемые старые файлы и заменены неактуальные тесты.

Не развёртывайте `wrangler.jsonc` автоматически: в нём нет полной записи существующей D1-базы `KITSUNE_DB`, которая настроена через Dashboard. Перед отдельным обновлением Worker сверяйте bindings, фактические database_name/database_id, Secrets, Origin, Google client ID и лимитеры. Не создавайте новую базу вместо действующей и не меняйте идентификатор владельца ради очистки репозитория.

Проверка локального серверного контракта: из `cloudflare-broker` выполните `npm run check`. Это тесты на имитациях, а не запросы с настоящими ключами. [Подключение Qwen](QWEN_API.md).

## PATCH

Смотрите manifest конкретного патча: база должна совпадать. Патч может включать список удаляемых устаревших файлов. Сначала сохраните копию приложения; затем проверяйте SHA-256 исходных заменяемых/удаляемых файлов. При собственных изменениях нельзя применять удаление вслепую. Предпочтителен LOCAL в отдельной папке, если версия базы неизвестна.

Патч этой версии предназначен для **3.1.0-rc.1 LOCAL**, не для старой GitHub beta и не для alpha.7. Распакуйте PATCH_ONLY в отдельную папку, остановите сервер целевой копии и запустите из PowerShell:

```powershell
.\APPLY_PATCH.ps1 -Target 'C:\путь\к\Kitsune_Math_RC1'
```

Сценарий проверяет версию и контрольные суммы до изменений, сохраняет резервные копии затрагиваемых файлов в соседней папке `.backup-...`, затем копирует новые файлы и удаляет только перечисленные устаревшие файлы. Если исходные файлы изменены, он останавливается. Хранилище браузера сценарий не трогает. Не распаковывайте патч поверх RC1 вручную до запуска сценария: это нарушит проверку исходных сумм.

## Откат

История Git сохраняется; force push и переписывание истории не используются. Для серверных исходников используйте обычный revert нужного commit и повторную публикацию. Для PWA предпочтительно выпустить исправленную оболочку с новым уникальным номером cache: возврат к ранее использованному имени cache может конфликтовать с ещё открытыми окнами.

Прогресс, D1, Secrets и модели не удаляются для отката интерфейса. Резервная копия файлов не является копией localStorage/IndexedDB. После любой операции проверьте привычный урок, старый прогресс и облачное подключение отдельно.
