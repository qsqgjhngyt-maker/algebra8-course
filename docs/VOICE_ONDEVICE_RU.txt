Историческое состояние v0.5. Актуальное продолжение с реальными моделями:
VOICE_V06_RU.txt. Ниже сохранено прежнее описание подготовительного этапа.

Kitsune: автономная генерация на Android, iOS и ПК

Статус: ПОДГОТОВИТЕЛЬНЫЙ ЭТАП. Автономный генератор ещё не создан.
Изменения не опубликованы в действующую GitHub Pages PWA.

Требование
Новые, заранее неизвестные фразы должны создаваться на самом устройстве
без сети, внешнего сервиса и работающего другого ПК. Первая загрузка
локальной модели допустима; последующее чтение должно работать офлайн.
Один собственный голос Kitsune, включение/выключение голоса и автоозвучки,
остановка без наложения. Отдельные статические WAV и отдельная модель TTS.

Что уже сделано в подготовленной ветке
Обычные кнопки чтения используют сохранённые WAV для точных известных
текстов; настройки больше не запускают параллельную пробную речь.
Старые голосовые профили, Irina/Dmitri, Silero и системный запасной голос
убраны из активного стека этой ветки. Распознавание микрофона и учебный
прогресс сохранены. Продакшен продолжает работать в прежней версии.
Пять утверждённых WAV v0.4, эталон и словарь не изменены: проверяются
21 исходный файл. Дополнительно готовы 28 технически проверенных WAV
трёх тем 1-1, 1-2, 1-3. Их прослушивание ещё не утверждено пользователем.
В текущей пробной сборке другие фразы показывают сообщение о недостающей
автономной модели. Нет подмены другим голосом или обращения к ПК.

Почему Qwen на ПК не решает это требование
Утверждённый голос получен siriusfreak/qwen3-tts-12hz-1.7b-ru-stress-cf
на CUDA ПК. Проверенная генерация на ПК не означает готовность браузерной
модели телефона. Ранее подготовленный PC bridge перенесён в архив
tools/voice-engine/experiments/pc-bridge-v05 и отключён от приложения
и тестового сервера. START_WITH_VOICE.bat теперь только открывает обычную
проверку готовых уроков, не запускает CUDA и не обеспечивает новый TTS.

Выбранное направление
Обучить компактную русскую модель единственного голоса Kitsune и
экспортировать её в ONNX. Локальный браузерный runtime WASM выполняет
синтез на CPU, поэтому WebGPU не должен быть обязательным условием.
Piper/VITS рассматривается как формат обучения собственной модели:
использование такого runtime не возвращает старые голоса и их настройки.
Список чужих голосов и сетевой запасной синтез в интерфейс не добавляются.
Браузерное Chatterbox multilingual поддерживает русский и клонирование,
но выбранный комплект q4 с декодером и энкодером составляет около 1,55 ГБ.
Это размер файлов, не измеренное потребление памяти. Работа на телефонах
не проверена. Он не выбран как готовое универсальное мобильное решение.
Supertonic 3 имеет русскую речь, но официальный открытый комплект не
содержит готового локального клонирования именно голоса Kitsune.

Подготовленные данные
Kitsune_Compact_Voice_Data_v05 содержит 33 исходных WAV, metadata.csv
и dataset.json с текстами, SHA256, группами уроков и статусом прослушивания.
Всего 245,60 с; WAV скопированы побайтно, не пересэмплированы.
Это частичный корпус, НЕ обученная модель и НЕ достаточное подтверждение
качества будущего голоса. Пять записей approved, 28 pending.
Формат CSV: имя WAV|фактически подготовленный произносимый текст.
Перед обучением нужны расширение корпуса и проверка соответствия речи
транскрипциям. Разделение для проверки следует делать по group/теме,
чтобы соседние фрагменты одного урока не попадали в разные выборки.

Из корня проекта экспорт только утверждённых записей:
  node tools/voice-engine/device/export-training-data.cjs --output <новый каталог>
С добавлением новых, ещё не прослушанных записей:
  node tools/voice-engine/device/export-training-data.cjs --include-unreviewed --output <новый каталог>
Существующий каталог экспорта не заменяется, оригинальные WAV не меняются.

Что отсутствует и препятствует завершению
В доступном проекте нет обученной компактной модели Kitsune ONNX/CKPT.
В текущем окружении нет пакетов обучения Piper/Lightning/ONNX export
и локального браузерного runtime. Загрузка через npm и обычный доступ
к исходникам из среды Codex завершаются ошибкой разрешения сетевого имени.
Существующий Qwen Python и его модель используются только для чтения;
изменять работающее утверждённое окружение для этих экспериментов нельзя.
Нужны отдельное окружение обучения и загрузка его зависимостей, затем
обучение/экспорт собственного голоса. Это ещё не выполнено.

Проверка готовности
assets/voice/kitsune_ondevice_v06/manifest.json имеет явный статус
awaiting_trained_model. В нём нет фиктивных весов или отметок тестирования.
  npm run voice:device-check
До получения модели эта команда возвращает код 2 — ожидаемый блок выпуска.
Для отчёта без ошибки:
  node tools/voice-engine/device/readiness.cjs --report
Проверка требует именно эталон Kitsune, реальные файлы модели и локального
runtime с SHA256, русскую одноголосую конфигурацию и отдельные результаты
для Android, iOS и ПК. Она не заменяет реальный синтез и прослушивание.
Также пока не написан и не подключён рабочий browser worker для этой модели.
dynamic-voice-v05.js сообщает её отсутствие; это не генератор.

Условия завершения следующего этапа
1. Достаточный проверенный корпус и обученная собственная компактная модель.
2. Полностью локальные файлы JS/WASM/фонемизатора/ONNX, без CDN после установки.
3. Штатные кнопки читают новую произвольную фразу через один worker/очередь.
4. После выключения сети и закрытия ПК телефон создаёт фразу, которой
   не было в готовых WAV и динамическом кэше; проверяются Android и iOS.
5. При остановке/повторном чтении поздний результат не начинает играть.
   Открытие настроек не запускает речь, выбор автоозвучки сохраняется.
6. Прослушивание нового голоса и измерение времени/памяти на устройствах.
7. Только затем отдельный релиз; до этого ветка не заменяет продакшен.
