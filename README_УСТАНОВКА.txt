Kitsune v2.3.0-beta.3.7.2 — отдельный контекст диалога

ПРОБЛЕМА
В beta.3.7.1 Router уже классифицировал только текущий вопрос, но после выбора
Cloud тематическая память всё ещё склеивалась с вопросом в одно поле message.
При росте истории суммарный текст превышал серверный лимит, Worker возвращал
local_only, и Router уходил в локальный fallback.

ИСПРАВЛЕНИЕ
Cloud-запрос теперь содержит два независимых поля:
- message — только текущий вопрос пользователя;
- conversationContext — компактная память темы.

Порядок:
текущий вопрос → Safety/Math/Tutor/Cloud Router → Cloud выбран
→ {message, conversationContext} → Worker → Qwen.

Безопасность:
- message сохраняет прежний лимит до 700 символов;
- conversationContext имеет отдельный серверный лимит до 1200 символов;
- клиентская память остаётся компактной (~920 символов);
- полный журнал и сырой звук не отправляются;
- чувствительный/некорректный context Worker просто отбрасывает, не ломая ответ;
- device proof подписывает и message, и conversationContext;
- старые запросы без context остаются совместимыми;
- Qwen получает память отдельным недоверенным служебным блоком, а текущий вопрос
  остаётся отдельным user message.

v2.3.0-beta.3.7.2 — Исправлена передача памяти в Cloud Brain

ОПИСАНИЕ
Тематическая память отделена от текущего сообщения пользователя и передаётся
в Worker отдельным подписанным полем conversationContext. Сохранён отдельный
лимит текущего вопроса, добавлена безопасная обработка контекста и обратная
совместимость запросов без памяти. Исправлен переход в локальный fallback при
росте истории диалога.
